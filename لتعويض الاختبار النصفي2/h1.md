# 🛡️ تحليل المخاطر الأمنية لنظام تسجيل الدخول

**تمرين تطبيقي: التهديدات الشائعة وطرق الدفاع البرمجي**

يعتبر نظام تسجيل الدخول هو الواجهة الأكثر استهدافاً في أي تطبيق ويب. يهدف هذا المختبر إلى فهم كيفية تأمين هذه البوابة ضد الهجمات الأكثر شيوعاً.

---

### 1. حقن SQL (SQL Injection) 💉

**الخطر:** استغلال حقول الإدخال لإرسال أوامر خبيثة لقاعدة البيانات لتخطي تسجيل الدخول أو سرقة البيانات.

- **❌ الممارسة الخاطئة:** دمج المتغيرات مباشرة في نص الاستعلام.
    
- **✅ الممارسة الصحيحة:** استخدام الاستعلامات المُحضرة (Prepared Statements).
    

PHP

```
// الكود الآمن
$stmt = $conn->prepare("SELECT * FROM users WHERE username = ? AND password = ?");
$stmt->bind_param("ss", $username, $password);
$stmt->execute();
```

---

### 2. تخزين كلمات المرور (Password Hashing) 🔑

**الخطر:** تخزين كلمات المرور كنص واضح (Plain Text) يجعلها عرضة للكشف فور اختراق قاعدة البيانات.

- **❌ الممارسة الخاطئة:** استخدام تشفير ضعيف أو قديم مثل `md5`.
    
- **✅ الممارسة الصحيحة:** استخدام خوارزمية **bcrypt** القوية.
    

PHP

```
// تخزين كلمة المرور بأمان
$hashed_password = password_hash($password, PASSWORD_BCRYPT);

// التحقق من كلمة المرور عند الدخول
if (password_verify($password, $user['password'])) {
    // دخول ناجح
}
```

---

### 3. هجمات القوة الغاشمة (Brute Force) 🔨

**الخطر:** محاولات آلية متكررة لتخمين كلمة المرور حتى الوصول للنتيجة الصحيحة.

**💡 الحل البرمجي (Rate Limiting):**

تحديد عدد المحاولات الفاشلة وإجبار النظام على التأخير الزمني (Sleep).

PHP

```
if ($login_failed) {
    $_SESSION['failed_attempts'] = ($_SESSION['failed_attempts'] ?? 0) + 1;
    if ($_SESSION['failed_attempts'] > 5) {
        sleep(5); // تأخير الخادم لمدة 5 ثوانٍ لتعطيل أدوات التخمين الآلي
    }
}
```

---

### 4. تسريب المعلومات (Information Disclosure) 📢

**الخطر:** إعطاء تلميحات للمهاجم تساعده في حصر أسماء المستخدمين الموجودة فعلياً في النظام.

- **❌ خطأ:** "اسم المستخدم غير موجود" (هذا يؤكد للمهاجم أن الاسم الذي جربه غير موجود).
    
- **✅ صحيح:** "اسم المستخدم أو كلمة المرور غير صحيحة" (رسالة موحدة لكل الحالات).
    

---

### 5. هجمات CSRF (تزوير الطلبات) 🕵️‍♂️

**الخطر:** خداع المستخدم المسجل للقيام بإجراءات (مثل تغيير كلمة مروره) دون علمه.

**🛡️ الحل باستخدام التوكن (CSRF Token):**

1. توليد رمز عشوائي في الجلسة.
    
2. إضافته كحقل مخفي في النموذج (Form).
    
3. التحقق منه عند استقبال الطلب.
    

PHP

```
// إنشاء الرمز
$_SESSION['csrf_token'] = bin2hex(random_bytes(32));

// التحقق من الرمز
if ($_POST['csrf_token'] !== $_SESSION['csrf_token']) {
    die("طلب غير شرعي!");
}
```

### 📊 ملخص مصفوفة الحماية

|**التهديد**|**مستوى الخطر**|**الحل التقني الأفضل**|
|---|---|---|
|**SQL Injection**|مرتفع جداً|Prepared Statements|
|**Brute Force**|متوسط|Rate Limiting & Captcha|
|**Data Breach**|مرتفع|Strong Hashing (Bcrypt)|
|**CSRF**|متوسط|CSRF Tokens|
