# تمرين تطبيقي: ثغرات حقن SQL (SQL Injection) والحماية منها

## 1. ثغرة حقن SQL (SQL Injection)

تحدث هذه الثغرة عندما يتم دمج مدخلات المستخدم مباشرة داخل استعلامات قاعدة البيانات، مما يسمح للمهاجم بتغيير منطق الاستعلام1.

### مثال على كود مصاب (تسجيل الدخول):

PHP

```
// خطأ: دمج مدخلات المستخدم مباشرة في الاستعلام
$username = $_POST['username'];
$password = $_POST['password'];

$sql = "SELECT * FROM users WHERE username = '$username' AND password = '$password'";
$result = mysqli_query($conn, $sql); // هذا الكود عرضة للاختراق
```

### السيناريو الهجومي:

يمكن للمهاجم إدخال قيم برمجية لتخطي عملية التحقق22.

- **اسم المستخدم الضار:** `' OR '1'='1` 3
    
- **النتيجة:** سيصبح الاستعلام دائماً صحيحاً (True)، مما يسمح بالدخول لأي حساب دون معرفة كلمة المرور4.

## 2. الحماية باستخدام الاستعلامات المُحضرة (Prepared Statements)

تعتبر الاستعلامات المُحضرة هي الطريقة الأكثر أماناً لمنع حقن SQL لأنها تفصل كود SQL عن البيانات5.

### (أ) الحماية باستخدام مكتبة MySQLi:

PHP

```
// استخدام علامات الاستفهام كعلامات حجز مكان (Placeholders)
$stmt = $conn->prepare("SELECT id, password FROM users WHERE username = ?");
$stmt->bind_param("s", $username); // ربط البيانات بأمان وتحديد النوع (s للنصوص)
$stmt->execute();
$result = $stmt->get_result();
```

### (ب) الحماية باستخدام PDO (PHP Data Objects):

تعتبر PDO أكثر مرونة لدعمها أنواعاً مختلفة من قواعد البيانات6.

PHP

```
$sql = "SELECT * FROM users WHERE email = :email";
$stmt = $pdo->prepare($sql);
$stmt->execute(['email' => $user_email]); // تمرير البيانات كمصفوفة
$user = $stmt->fetch();
```

## 3. مقارنة بين الطرق التقليدية والآمنة

|**المعيار**|**الاستعلام المباشر (Direct)**|**الاستعلام المُحضر (Prepared)**|
|---|---|---|
|**الأمان**|ضعيف جداً (عرضة للحقن) 7|قوي جداً (يمنع الحقن) 88|
|**الأداء**|أبطأ عند التكرار|أسرع عند تنفيذ نفس الاستعلام عدة مرات|
|**التعامل مع البيانات**|يتطلب تنظيف يدوي (Escaping)|يتم التعامل مع البيانات كقيم فقط وليس ككود|

---

## 4. أفضل الممارسات الأمنية لقواعد البيانات

- **استخدم دائماً Prepared Statements:** لا تضع أي متغير من المستخدم داخل نص الاستعلام مباشرة9999.
    
- **تشفير كلمات المرور:** لا تخزن كلمات المرور كنص واضح، استخدم دالة `password_hash()`10.
    
- **مبدأ الصلاحيات الأقل:** تأكد من أن مستخدم قاعدة البيانات لديه فقط الصلاحيات التي يحتاجها (مثلاً لا يحتاج صلاحية `DROP` لتطبيق عرض مقالات)11.
    
- **استخدام ORM:** مكتبات مثل Eloquent أو Doctrine توفر حماية تلقائية ضد هذه الثغرات في أغلب الحالات.
